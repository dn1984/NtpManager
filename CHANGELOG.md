# История версий

Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии соответствуют [Semantic Versioning](https://semver.org/lang/ru/).

## [1.5] — 2026-10-14

### Добавлено

- **Два языка интерфейса: русский и английский.** Переключатель **«Язык»** в верхней панели окна
  (применяется после перезапуска утилиты) и ключ `-Language ru|en`; по умолчанию язык определяется
  по системе: русская Windows — русский, иначе английский.
- Переведены: окно целиком (вкладки, группы, элементы, подсказки, диалоги, меню в области
  уведомлений), строки состояния, журнал работы и текстовый отчёт. Вывод самой Windows
  (`w32tm`, `netsh`, `netstat`) приводится как есть — его локализует сама система.
- Язык сохраняется в `NtpManager.settings.ini` (ключ `Language`), поэтому выбор сохраняется между
  запусками; первый запуск подбирает язык автоматически.

### Изменено

- Версия утилиты — 1.5.

## [1.4] — 2026-10-14

### Добавлено

- **Восстановление службы времени** одной кнопкой на вкладке «Служба» и ключом `-RestoreService`:
  выполняет `w32tm /register`, ставит тип запуска «Автоматически», запускает службу и показывает
  весь вывод. Нужно, когда службы нет в списке служб (после `w32tm /unregister` или удаления ключа).
- **Режим групповой политики**: галочка «Записывать параметры и в ветвь политики» (и ключ
  `-UsePolicyBranch`) — пишет те же параметры в `HKLM\SOFTWARE\Policies\Microsoft\W32Time`,
  что нужно, когда служба управляется политикой; перед записью ветвь политики сохраняется в рег-файл.
- Кнопки «Открыть gpedit» и «Удалить ветвь политики...» (с резервной копией и пояснением про
  «Не задано»).
- Диагностика регистрации службы: утилита различает «нет в менеджере служб, но ключ в реестре есть»
  и «не зарегистрирована в системе» и подсказывает, что делать.
- Защита от бессмысленной регистрации: если `%windir%\system32\w32time.dll` отсутствует, операция
  не выполняется и выдаётся рекомендация `sfc /scannow`.

### Изменено

- Версия утилиты — 1.4; заголовок скрипта дополнен новыми режимами.
- В документации явно перечислены поддерживаемые версии Windows (7 / Server 2008 R2 … 11 / Server 2025)
  и описано, что утилита делает по-разному в зависимости от версии (движок PowerShell, источник событий,
  Server Core, домен/рабочая группа).

### Исправлено

- **Совместимость с PowerShell 2.0 (Windows Server 2008 R2):** в этой версии `foreach` по `$null`
  выполняет тело один раз, а `@($null)` даёт массив из одного пустого элемента. Из-за этого пустой
  ответ WMI рождал «пустую службу» и ложное предупреждение «возможен конфликт за порт 123»,
  а пустой список слушателей мог быть принят за посторонний процесс. Теперь пустые элементы
  явно отфильтровываются во всех подобных местах.
- **События службы времени на новых версиях Windows:** добавлено чтение современного поставщика
  `Microsoft-Windows-Time-Service` (Windows 8 / Server 2012 и новее, включая 10/11) через
  `Get-WinEvent -FilterXPath`; классический источник `W32Time` (2008 R2 / 7) остаётся резервным.
  До этого на Windows 10/11 строка «Последнее событие W32Time» показывала «нет записей».
- Защита строки событий от пустых значений (в PowerShell 2.0 это могло привести к ошибке при
  построении строки состояния).

## [1.3] — 2026-10-13

### Добавлено

- Проверка групповой политики: строка состояния «Групповая политика службы времени» перечисляет
  параметры, заданные политикой, и предупреждает, что политика важнее реестра.
- Определение домена/рабочей группы (WMI `PartOfDomain`) — чтобы правильно объяснить источник политики.
- Предупреждение о политике в предпросмотре изменений и в окне подтверждения.

## [1.2] — 2026-10-13

### Исправлено

- **Ложное предупреждение «порт слушает посторонний процесс (svchost)».** Владелец порта 123 теперь
  определяется не только по PID службы, но и по составу служб внутри процесса-слушателя: служба
  времени живёт внутри общего процесса `svchost.exe`, и это норма, а не конфликт.
- Кэш PID службы больше не «отравляется» нулевым значением при старте в облегчённом режиме;
  при подозрении на конфликт порт перепроверяется, кэш самолечится.
- При запуске окна сразу выполняется полная проверка (раньше первая была облегчённой).

### Добавлено

- Поясняющая строка «Как работает служба времени» (служба внутри `svchost` — так и должно быть).
- Расширенный текст предупреждения о реальном конфликте: что делать со сторонним NTP-сервисом.

## [1.1] — 2026-10-13

### Исправлено

- Наложение подписей полей в группе «Прочее» и уход кнопок применения под прокрутку: все вкладки
  переведены на докинг, кнопки всегда видны внизу (проверено: 0 наложений).
- Строка предпросмотра типа запуска службы печатала значение по-английски (`Автоматически -> Automatic`).

### Изменено

- **Устранены «фризы» интерфейса:** автообновление выполняет только лёгкую проверку (служба и реестр,
  ~50 мс вместо ~2500 мс); тяжёлые проверки кешируются и выполняются по кнопке или раз в 10 минут;
  дорогой перебор журнала событий — не чаще раза в 10 минут; опрос NTP-сервера по таймеру по умолчанию
  выключен.
- Кнопки раздела «Команды w32tm» переименованы в понятные («Состояние синхронизации», «Источники
  времени», «Замеры с сервера (5)» и т. д.).

### Добавлено

- Всплывающие подсказки ко всем элементам окна и подробная справка по кнопке «Справка».
- Галочка «дописывать флаг ,0x9 самому»: достаточно ввести только IP-адрес GPS-сервера.
- Подписи-пояснения у необязательных полей `MaxAllowedPhaseOffset` и `EventLogFlags`.
- Ключ `-ReportFile` — запись полного отчёта в файл (UTF-8).

## [1.0] — 2026-10-13

### Добавлено

- Первая версия: графическое окно с вкладками «Состояние», «Служба», «Настройка», «Диагностика»;
  управление службой времени; настройка провайдеров `NtpServer` и `NtpClient` с предпросмотром
  изменений и автоматической резервной копией реестра; проверка серверов встроенным SNTP-клиентом;
  управление правилом брандмауэра для UDP 123; журнал работы; командная строка `-Report` / `-Apply` /
  `-Help` с кодами возврата 0/1/2.
